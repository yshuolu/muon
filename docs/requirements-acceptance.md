## Product limits within the requested local release

The product does not merge branches, push, deploy, or edit source directly in the task UI. Completed work remains in its task branch with evidence for owner review. Group completion is based on successful children and dependencies and never fabricates an RFC or verification run for the group itself. Cloud execution, PostgreSQL, project switching, multiple users, and configurable workflows are interface-compatible future work, not exposed placeholder controls.

Agents may call their configured model services even though orchestration, storage, and agent processes run locally. Textual verification reports are validated for concrete test steps and results; they are still agent-reported evidence. Independent host reruns strengthen the live acceptance checks but are not a general attestation mechanism for every future task.

Claude defaults to npm-registry access for approved commands. Additional test/dependency hosts and local preview listeners are explicit owner runtime configuration; see [configuration](../README.md#configuration). These settings do not change the RFC approval gate.
